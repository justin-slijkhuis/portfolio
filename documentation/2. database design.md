I decided to start with the database design instead of the architecture since most of the MoSCoW requirements are data related. This makes it easier for me to come up with an architecture which is data oriented. Below is an image displaying the most recent version of the physical data model.

## How I designed this model

I will not go in full detail yet about how this is designed. This will be done on the project page in the actual portfolio. I will however give a brief overview of the design process.

### Ordering

One of the key aspects that I spend time on is the order that different data is shown. For example: I included a pinned column with datatype BIT(1) to the Projects table which allows me to pin two projects at the very top. The column allows me to specify the order of the pinned projects by using BIT(1) together with two partial UNIQUE modifiers which means only a single record can have the value 0 (the first project), a single record can have the value 1 (the second project) and as many records can have the value NULL. The projects with value NULL are ordered by the date they were finished. This means current incomplete projects are at the very top followed by the most recently completed projects.

The order that things will be shown comes back multiple times in the design. A good example is the cloud on the relation between Roles and Experiences which indicate that the intermediate table requires an extra column for ordering. In specific it is on the side of the Roles table which means that it is supposed to be used when retrieving the experiences for a specific role and not when retrieving all roles for a specific experience. So let's say I have a role called "Full-stack developer" where I have specified the experiences Python, JavaScript and C#. Now C# and JavaScript have way more priority here than Python since it is less commonly used in the role of a full-stack developer. This means that I want to show C# and JavaScript first and then Python which is what the order is for. Now if I were to retrieve all roles for a specific experience, then I think it is better to show the most recent role where I used/learned/improved that experience. That is why there is only going to be one column for ordering in the intermediate table which is for the Roles table.

### Posts visual editor

One of the most difficult parts about the CMS is the Posts section. It consists of a visual editor where I can create or edit a post using the components that I have created in the frontend. Much like WordPress Gutenberg. The difficult part is storing the page in a way that can be retrieved fast which also handles component changes well. WordPress uses a custom string to store the page which is then parsed by the frontend. At first I wanted to do the same, yet this isn't efficient and hard to work with.

Next I thought it would be a good idea to store this in an array of JSON values where the index decides the order of the components and each JSON value is one of those components. Each JSON will have a key called component to specify what component it is and the other keys are used to specify the attributes of that component. This is easier to work with, but I doubt it is faster than the string method and even if it is, then it still isn't quite the speed I am looking for.

Lastly there was the idea of creating a .tsx file for each post when it is created or edited. This file will be stored in /routes/posts/{postId}. This is the fastest method since the frontend can just import the file and use it as a component. It does however not allow for statically generating the page unless I restart the website which now builds the .tsx file. This is also very experimental.

Then I saw something Qwik can do which is dangerously specifying inner HTML. I have never used this before. So I will be building a prototype to test if I can use text as a way to build a page just like shown below. The prototype will also be used to find a way to display + select all components in the frontend and be able to alter properties of the component for it to become a true visual editor. Read about the prototype [here](./3.%20prototype%20posts.md);
