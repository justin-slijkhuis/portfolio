# Requirements

## ISO 25010

The requirements below follow the ISO 25010 standard. In case I use a different name, then the actual name will be specified in the brackets. For this portfolio, I will write tests for most of the requirements to make sure they succeed. The portfolio will be deployed using a pipeline which will run the tests before deploying the portfolio to ensure everything is okay before release.

### Accessibility (inclusivity & user assistance)

Everyone has to be able to use my portfolio. To challenge myself, I will be setting a high accessibility requirement. These are required for the portfolio part and are preferred for the CMS part.

- **[accessibility-01]** The portfolio has to follow Web Content Accessibility Guidelines (WCAG) version 2.2 where a minimum rating of AA is required on all aspects or a rating of A if that is the maximum rating for that aspect.

- **[accessibility-02]** Lighthouse, Axe and WAVE must not give any errors or warnings on any pages.

- **[accessibility-03]** Creating new Posts using the visual editor must force the user to create accessible content.

### Performance (time-behaviour)

Performance is insanely important to me, which I want to reflect on my portfolio. So I will be setting a high performance requirement. These are required for the portfolio part and are preferred for the CMS part.

- **[performance-01]** The portfolio must have a Lighthouse performance rating of at least 90 on all pages.

- **[performance-02]** All pages should have an FCP of less than 1.8 seconds

- **[performance-03]** All pages should have an LCP of less than 2.5 seconds

- **[performance-04]** All pages should have a CLS score of less than 0.1

- **[performance-05]** All pages should have a TBT of less than 0.2 seconds

- **[performance-06]** All pages should have a TTI of less than 3.5 seconds

- **[performance-07]** All pages should have a TTFB of less than 0.8 seconds

- **[performance-08]** All interactions should have an INP of less than 200 milliseconds.

- **[performance-09]** All pages should have a FID of less than 100 milliseconds.

- **[performance-10]** All pages should have a speed index of less than 3.4 seconds.

- **[performance-11]** Displaying a list of content must use lazy loading or pagination to ensure adding content doesn't slow down the page loading time.

### Capacity

The portfolio has to be able to handle multiple users at the same time. These are required for the portfolio part.

- **[capacity-01]** The portfolio has to be able to handle 100 users at the same time.

### Availability

The portfolio has to be available at all times. These are required for the portfolio part and are preferred for the CMS part.

- **[availability-01]** The portfolio has to be available 99.99% of the time.

### Integrity

The CMS has to be secured in a way that makes sure someone can't change the portfolio making me look different than I am or deleting aspects about me.

- **[integrity-01]** The CMS must only be able to be accessed by devices that are white-listed.

- **[integrity-02]** The CMS must require a strong password to access.

- **[integrity-03]** The CMS must require two-factor authentication to access.

- **[integrity-04]** The database must only be accessible by the CMS.

- **[integrity-05]** The database connection attributes must only be able to be viewed by the released CMS.

- **[integrity-06]** The user must always login when opening the CMS, even if they logged in within the last 5 minutes.

### Recoverability

The portfolio has to be able to recover from disasters like someone deleting or changing data without my permission.

- **[recoverability-01]** There must be a backup of the database every 24 hours.

- **[recoverability-02]** A backup must be stored for at least 10 days.

### User engagement

The portfolio has to be engaging to the user to browse further and get to know me better.

- **[user-engagement-01]** The portfolio must have a light and dark mode.

- **[user-engagement-02]** The portfolio must have a clear navigation bar which specifies all important pages.

- **[user-engagement-03]** The portfolio must contain at least a few animations to make the portfolio more engaging.

- **[user-engagement-04]** Aspects of the portfolio must reference each other to navigate between them.

- **[user-engagement-05]** The homepage must encourage users to view all the different important pages.

### Analysability

The portfolio has to be able to be analysed to see how many people are visiting the portfolio and where they are from.

- **[analysability-01]** The portfolio must have Google Analytics or a similar tool installed.

### Confidentiality

The portfolio has to be confidential to the user.

- **[confidentiality-01]** The portfolio must have cookies to store user preferences for being analyzed.

- **[confidentiality-02]** Any reference to a colleague must be approved by the colleague in text form, otherwise it must be shown as anonymous.

### Scalability

I don't imagine the website becoming so big it needs to scale. Yet for future proofing the posts part, I will have a slight requirement.

- **[scalability-01]** The portfolio part of the website must be able to scale vertically within 12 hours.
